# Verdigris — an original oxidized-copper colorscheme for the sway desktop

An original scheme, built from scratch for this dotfiles repo — not a port
of anything. Where Litho/Vellum/Daguerre are strictly grayscale, Verdigris
is the one full-color family left in this repo: a desaturated teal-charcoal
(dark) or warm parchment (light) neutral range, one warm copper/terracotta
accent, and a small set of muted, naturalistic hues for the semantic roles
(rust red, patina green, dull gold, dusty plum) rather than saturated
primaries — the idea is oxidized copper on a weathered patina surface.
**Two variants only** — `dark` and `light` — no dusk equivalent, matching
the other three families now that this repo has been simplified down to
four total.

## Where the colors come from

Every value is original and hand-picked; see `dark/palette.md` and
`light/palette.md` for the full swatch list, including the note on how
kitty's ANSI blue/cyan slots (this palette has no true blue or cyan) fall
back to `link`, the teal accent.

## Wallpapers

Desktop wallpaper and swaylock's lock-screen background are generated by
`~/.cfg-tzevaot/bin/scheme_wallpaper.py` — the only wallpaper generator in
this repo now (`palette_wallpaper.py` and the five families it served were
retired). Verdigris's desktop uses the `patina` pattern (blurred oxidation
blotches fading from `bg` to `bg_header`, with warm `accent` breaking
through in smaller, sparser patches — the weathered-copper feel); the
lockscreen uses `glow` (a radial vignette from `accent` to `bg`), the same
pattern every family's lockscreen uses. Regenerate with:

```
scheme_wallpaper.py --palette verdigris_dark  --pattern patina --seed 11 --output ~/.img/wallpapers/verdigris_dark_desktop.png
scheme_wallpaper.py --palette verdigris_dark  --pattern glow   --output ~/.img/wallpapers/verdigris_dark_lockscreen.png
scheme_wallpaper.py --palette verdigris_light --pattern patina --seed 11 --output ~/.img/wallpapers/verdigris_light_desktop.png
scheme_wallpaper.py --palette verdigris_light --pattern glow   --output ~/.img/wallpapers/verdigris_light_lockscreen.png
```

## Layout

```
verdigris/
  dark/    — one file per app, Verdigris Dark values, in that app's native syntax
  light/   — same, Verdigris Light values
  active -> dark | light   (symlink; this is what every app config points at)
```

Same wiring as Litho/Vellum/Daguerre — `sway/config`, `mako/config`,
`waybar/style.css`, `wofi/style.css` each include/`@import`
`<theme>/active/...`; `swaylock` has no include mechanism so
`verdigris-theme` copies the variant's config over `swaywm/swaylock/config`
directly; kitty and vim pick their colorscheme independently as ordinary
toggle options (`kitty/colors/verdigris_{dark,light}.conf`,
`vim/colors/verdigris_{dark,light}.vim`).

Verdigris also ships a KDE Frameworks color scheme
(`{dark,light}/Verdigris{Dark,Light}.colors`) — **deliberately not wired
into `verdigris-theme`**, same as the other families' KDE schemes. Apply
one with `plasma-apply-colorscheme VerdigrisDark` (or `VerdigrisLight`)
after symlinking/copying the `.colors` file into
`~/.local/share/color-schemes/`.

## Coexisting with other themes

Only one theme family drives sway/mako/waybar/wofi's chrome at a time —
whichever of `litho-theme`/`vellum-theme`/`daguerre-theme`/
`verdigris-theme` ran most recently. Each script rewrites the shared
`swaywm/<family>/active/...` include paths to point at itself. kitty and
vim are unaffected — every theme's variants sit side by side as ordinary
flat toggle/colorscheme options.

## Switching

```
verdigris-theme dark    # switch everything (except vim) to Verdigris Dark
verdigris-theme light   # switch everything (except vim) to Verdigris Light
verdigris-theme toggle  # flip dark <-> light
verdigris-theme status  # show which variant is active
```

Reloads sway (`swaymsg reload`), mako (`makoctl reload`) and waybar
(`SIGUSR2`) itself; kitty picks up the new include on next launch, or press
ctrl+shift+F5 in an open kitty window to reload it live. For vim, run
`:colorscheme verdigris_dark` (or `_light`) in a running session, or change
the `colorscheme` line in `vimrc` if you want it to be the new default.
